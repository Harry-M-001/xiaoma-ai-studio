# 画布体检与修

## 诊断顺序（不要跳步）

1. `get_canvas`：先把节点与连线读出来（**没读过就不要下结论**）；
2. `summarize_canvas`：给用户复述一遍现状，让他确认「说的就是这张」；
3. `lint_canvas`：分镜层面的问题（景别单调、运镜雷同、AI 腔）；
4. `preview_canvas`：哪些节点缺输入会被跳过、哪些已有产物会重做、至少几次调用；
5. 只有前四步都做完，才动手改。

## 修的时候

- **改节点用 `update_node`**，参数只传契约里允许的键（被忽略的键会在 `ignored_params` 里）；
- **连线的端口类型必须匹配**（文本→文本、图片→图片），不合法会被后端拒绝；
- 改完再跑一次 `preview_canvas` 或 `lint_canvas` 复核，**用工具结果说话**。

## 绝对不要

- 不要因为「看起来不对」就 `apply_canvas_draft` 重建整条链——用户手调过的提示词会没；
- 不要自己 `run_canvas`；它必须由用户点确认；
- 不要凭记忆说「应该能跑」——`preview_canvas` 的 blocked 列表才是判据。

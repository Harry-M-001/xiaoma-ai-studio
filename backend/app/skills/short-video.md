# 短视频生产

## 什么时候用

用户要**一条能看的片子**，而不是只要一段文字。典型说法：「做一条 30 秒的短片」「把这个点子拍出来」「帮我搭条视频链路」。

## 链路（节点顺序固定，不要自创）

1. `idea` 创意策划：一句话 → 结构化的故事骨架
2. `novel` 小说：把骨架写成有画面的文字（短片的长度通常 800–1500 字）
3. `script` 剧本：分场景、分台词
4. `storyboard` 分镜：逐镜的画面描述 + 台词 + 时长
5. `storyboardImage` 分镜图：逐镜出图（**最花钱的一步**）
6. `video` 视频：逐镜出片，再接成片

短片的画幅默认 `9:16`，除非用户说要横屏。每镜时长先按 3–5 秒打算，总时长倒推镜数。

## 干活顺序（这条比结果重要）

1. **先 `draft_canvas` 出草稿**，把节点与提示词给用户看；
2. 用户认可再 `apply_canvas_draft`；
3. **`lint_canvas` 体检**（景别单调 / 运镜雷同 / AI 腔），把问题念给用户；
4. **`preview_canvas` 报成本**：几次调用、哪些节点会重做；
5. **不要自己 `run_canvas`**——它会停下来让用户点确认，这是设计，不是卡住。

## 常见坑

- 分镜图的张数 = 分镜行数，**一多就是一大笔**；先让用户确认镜数。
- 视频节点依赖分镜表文本，别只连分镜图；否则会报「没能解析出分镜表」。
- 逐镜出片时首尾帧能提高连贯性，但会多一次截帧调用。
- 用户改了一句需求，**只改受影响的节点**（`update_node`），不要整条重建。

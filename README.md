# 小马AI工坊 · XiaoMa AI Studio

> 一个部署在自己电脑上的个人 AI 创作工作台：填一个接口地址和 API Key，就能接入任意模型，完成**文本对话、图片生成、视频生成**，或在画布上把节点连成工作流一键执行，产物自动沉淀到本地资产库。

- **BYOK（自带密钥）**：不内置任何厂商账号，不经过任何第三方中转。你填写的 Base URL 和 API Key 只保存在你自己的机器上（本地加密存储）。
- **开放接入**：支持所有 OpenAI 兼容接口（OpenAI、DeepSeek、Kimi、通义千问、智谱、OpenRouter、本地 Ollama 等），以及火山方舟 Ark（豆包 Seedream 图片 / Seedance 视频）。
- **稳定优先**：SQLite + 本地文件存储，无外部依赖；生成任务后台运行、重启自动恢复，失败有可读错误。
- **开箱即用**：Windows 双击 `start.bat` 一键启动，也支持 macOS / Linux 与 Docker。

## 功能一览

| 模块 | 能力 |
| --- | --- |
| 首页 | 打开即达的创作总览：快捷入口卡片、最近项目、一键新建项目；导航抽屉可收起为图标条 |
| 项目 | 一次完整作品的容器：创建 / 重命名 / 删除，每个项目内置一张可视化画布 |
| 画布 | 节点式工作流编排（ReactFlow）：文本 / 创意策划 / 小说 / 剧本 / 分镜 / 资产表 / 图片生成 / 资产设定图 / 分镜图 / 视频生成 / ComfyUI 工作流十一类节点，拖拽连线按端口类型实时校验（防环、防类型不匹配），单节点或整图一键执行，上游产物自动作为下游输入（文本拼接提示词、图片作参考图/首帧），运行状态与缩略图直接显示在节点上 |
| 自动链 | 从一句话创意到分镜的完整流水线：工具栏选档位点「自动链」即可铺好节点（L1 文本链 / L2 追加资产链 / L3 再追加分镜图 / L4 再追加逐镜视频），逐步或整图执行；每个阶段一个 Agent（提示词可在系统设置里改），内容层全部是 Markdown 正文，长文自动分块续写（先出大纲再逐章/逐场/逐镜生成），避免被模型输出上限截断；产物落盘为 `.md` 进资产库，同时作为下游节点的输入。**任一阶段的正文都能在画布上点开大弹窗直接改**，改完下游立刻读这份，不必重跑 |
| 资产链 | 角色/场景/道具的一致性方案：资产表节点把上游内容整理成 Markdown 表格，资产设定图节点逐行生成设定图（角色三视图+特写 / 场景广角空镜 / 道具多角度）并按资产名入库；下游图片、视频节点提示词里**提到资产名就自动挂对应设定图当参考**，无需手动选图（可在浮框里关掉，或按角色/场景/道具设定生成范围） |
| 导演风格库 | 12 张风格卡（8 位导演技法 + 国漫 / 赛博朋克 / 水墨 / 纪实手持）：在小说 / 剧本 / 分镜 / 分镜图 / 视频节点上选一次「风格」，就会在三处自动注入——分镜 Agent 的系统提示词、生图提示词的英文技法片段、生视频提示词的运镜片段。**导演名只给 LLM 理解技法，永远不写进生图/生视频提示词**（合规边界写死在数据层）；风格卡可在「系统设置 → 导演风格」里改，改完立即生效 |
| 分镜图 | 读分镜表**逐镜出图**：每镜用它自己的「首帧提示词」，自动追加所选风格的技法词；**每一镜单独做一次角色提及注入**，只挂这一镜提到的那几个角色，而不是把整批设定图全塞进去。浮框里可设「生成镜数」（0 = 全部，上限 24 镜） |
| **ComfyUI 工作流** | 接入本机 ComfyUI（默认 `http://127.0.0.1:8188`）：上传 `workflow_api.json` 后，后端按节点类型自动发现可调参数（模型 / 步数 / CFG / 采样器 / 宽高 / 帧数 / 提示词 / 种子 / 参考图），画布浮框按参数表动态渲染表单，运行时可临时调分辨率、时长等；产物（图片或视频）自动落库并下传下游节点 |
| 文本对话 | 多轮上下文、SSE 流式输出、会话管理、历史持久化 |
| 图片生成 | 文生图、多比例、批量（1-4 张）、参考图（图生图，视模型支持）；**批量模式**：多行提示词 × 多模型对比，一次提交自动排队执行 |
| 视频生成 | 文生视频 / 图生视频、时长 / 画幅 / 清晰度参数、后台任务轮询；**逐镜出视频**：读上游分镜表，一镜一段，每镜用自己那张分镜图当首帧，可选「并接首尾帧」让上一镜的尾帧接下一镜的首帧、「同场景参考串联」保证同场戏镜头接得上 |
| 提示词库 | 可复用模板：内置 10 个常用模板，支持搜索 / 筛选 / 新建 / 编辑 / 删除，一键套用到对话、图片、视频创作页 |
| 任务中心 | 全部生成任务集中管理：状态筛选、进行中自动刷新、**重新生成沿用当时的参数快照**（只改你在弹窗里显式改的项，重跑出来的任务仍挂在原画布节点上）、**产物一键在文件管理器里打开**、取消 / 删除；生成前可开启二次确认防误触 |
| 导演台 | 本地视频粗剪：导入视频 → 标记入/出点 → FFmpeg 截取片段 → 时间线排序 → 合并导出成片；片段可一键送去「AI 改造」（作为首帧图生视频）。自动检测 FFmpeg，未安装时给出各系统安装指引 |
| 资产库 | 所有产物与上传素材本地归档、预览、下载、删除、分页 |
| 模型服务 | 多服务管理、服务商预设、连接测试、按能力（文本/图片/视频）配置模型、一键启停；**粘贴一个 Key 就接入**（自动认归属、发一次真实请求、通了才保存）、**自动检测本机 Ollama 并一键接入**（不需要云账号） |
| 在线更新 | 「系统设置 → 关于与更新」查看当前版本与代码提交；有新版本时直接点「一键更新」（git pull → 依赖清单变了才装依赖 → 前端有改动才重建）。更新源支持 Gitee / GitHub，一个不通会自动换另一个；Docker 与压缩包安装会给出对应的升级做法 |
| 安全与体验 | 可选访问口令、密钥本地加密、明/暗色主题、响应式布局 |

## 技术栈

- 前端：React 18 + TypeScript + Vite 6，无重型 UI 框架，手写设计系统（CSS 变量双主题）；画布编辑器基于 ReactFlow（`@xyflow/react`）
- 后端：Python 3.11+ / FastAPI / SQLAlchemy（async）/ SQLite
- 部署：单机进程；前端构建产物由后端直接托管，一个端口对外

## 下载项目

**推荐用 `git clone`**。不是为了赶时髦：应用内的「一键更新」只在 git 安装下可用（走 `git pull --ff-only`，依赖或前端有变化才重装重建）；压缩包安装只能自己在设置页看到「有新版本」，然后手动去 Releases 重新下载覆盖。

### 方式 0：Windows 便携包（解压即用，不需要装 Python）

在 [Releases](https://github.com/Harry-M-001/xiaoma-ai-studio/releases) 里下载 **`xiaoma-ai-studio-vX.Y.Z-win64-portable.zip`**（约 21 MB），解压到任意目录，双击里面的 `start.bat`，浏览器打开 `http://127.0.0.1:8787` 即可。包内自带 Python 运行时与全部依赖，**不会在用户机器上编译或联网安装任何东西**。

适合「只想先用起来看看」的场景；因为它不是 git 安装，应用内的「一键更新」不可用，升级方式是用新包替换程序目录（**保留 `backend/data` 目录**，你的数据与密钥都在那里）。

> ⚠️ **别下错包**：GitHub 在源码页会自动生成 `Source code (zip)` 这类压缩包，那是**源码**，里面既没有运行时也没有启动脚本，解压后双击 `.bat` 只会得到一个报错。认准 Releases 页里带 `portable` 的那个附件。

### ⚠️ 放在哪个目录（重要）

- **不要**把本项目放进 ComfyUI 的 `custom_nodes` 目录。那不是插件，是一个独立的 Web 服务：放进去之后 ComfyUI 会把它当插件加载，而且 ComfyUI 整合包带的是**嵌入式 Python**（没有 `venv` 模块），会导致一键启动脚本在「创建虚拟环境 / 安装后端依赖」这一步反复失败。
- 正确做法是放在任意普通目录，例如 `D:\xiaoma-ai-studio`，让它自己起一个 8787 端口的服务；ComfyUI 通过「本机工作流」的方式单独接入即可，**两边各自独立运行**。

## 快速开始

下面三种启动方式都假设你已经按上一节把代码拿到本地了。

### 方式一：一键脚本（推荐）

需要本机已安装 **Python 3.11+** 和 **Node.js 20+**。

- Windows：双击 `start.bat`（或在终端中运行）
- macOS / Linux：

```bash
chmod +x start.sh
./start.sh
```

脚本会自动创建虚拟环境、安装依赖、构建前端并启动服务。看到提示后，浏览器打开：

```
http://127.0.0.1:8787
```

### 方式二：Docker

```bash
docker compose up -d --build
# 打开 http://127.0.0.1:8787
```

数据（数据库、生成的图片/视频）持久化在仓库根目录的 `./data` 中。

### 方式三：开发模式（热更新）

终端 1（后端，8787 端口）：

```bash
cd backend
python -m venv venv
# Windows: venv\Scripts\activate    macOS/Linux: source venv/bin/activate
pip install -r requirements.txt
uvicorn app.main:app --reload --port 8787
```

终端 2（前端，5173 端口，自动代理 /api 到 8787）：

```bash

```

打开 http://127.0.0.1:5173 。

## 使用三步

1. **接入一个模型**。两条路，都不必先读文档：
   - 本机装了 [Ollama](https://ollama.com)？应用会自动检测到，界面上点一次「一键接入」即可（不需要任何账号，完全本地跑）。
   - 有云服务商的 Key？到「**模型服务**」页顶部把它**粘进去**——应用会认出这是哪家的 Key、用预设地址发一次真实请求，**通了才保存**，不必手填协议、地址与模型名。
   - 界面顶部会有引导横幅告诉你当前能不能开始创作；已经接入但缺某一类模型（比如缺视频模型）时也会提醒。
2. 想先看看这东西能做出什么：首页或项目页点「**从示例开始**」，会按你现有的模型铺一条**跑得动**的链（只接了文本模型就铺 L1 文本链），第一个节点里已经写好了一句创意，点「运行整图」就能看到产出。
3. 之后回到「文本对话 / 图片生成 / 视频生成」，在顶部选择模型即可开始。生成结果自动进入「资产库」。

手动添加服务、以及常见服务商的 Base URL 与模型名，见 [docs/providers.md](./docs/providers.md)（在「模型服务」里选预设也能自动填好地址与常用模型）。

### 画布工作流（进阶玩法）

1. 在「项目」里创建或打开一个项目，点击「打开画布」进入可视化编辑器。
2. 从左侧面板添加节点（文本 / 创意策划 / 小说 / 剧本 / 分镜 / 资产表 / 图片生成 / 资产设定图 / 分镜图 / 视频生成 / ComfyUI 工作流），在节点下方浮框里配置提示词、模型与参数；拖线连接节点，端口类型不匹配或会成环的连线会被实时拒绝。
3. 单个节点点「运行此节点」单独执行；工具栏「运行整图」按依赖顺序自动依次执行——上游文本会拼进下游提示词，上游图片自动作为参考图或视频首帧，产物缩略图与文档正文直接显示在节点上。

### 自动链：从一句话创意到成片

画布工具栏选好档位后点「**自动链**」，会一键铺好节点并连好线：

```
L1 文本链：  创意策划 ──→ 小说 ──→ 剧本 ──→ 分镜

L2 +资产链： 创意策划 ──→ 小说 ──→ 剧本 ──→ 分镜 ──→ 资产表 ──→ 资产设定图

L3 +分镜图： 创意策划 ──→ 小说 ──→ 剧本 ──→ 分镜 ──→ 资产表 ──→ 资产设定图
                                              │                    │
                                              └──→ 分镜图 ←────────┘

L4 +逐镜视频：在 L3 之后再挂一个视频节点，读分镜表逐镜出片（详见下方「逐镜出视频」）
```

- 在「创意策划」节点填一句想法（例如"外卖小哥其实是隐退的顶级保镖"），点「运行整图」，各阶段会依次跑完。
- 每个阶段是一个可配置的 Agent（系统设置 → **创作 Agent**），提示词、输出格式、温度、单次输出上限都能改。改完立即生效，不用改代码。
- **长文不会丢**：小说 / 剧本 / 分镜都配了「先出大纲 → 再逐章 / 逐场 / 逐镜续写」的分块机制，节点浮框里的「章数 / 场数 / 镜头数」就是块数。这是刻意的设计——单次调用输出有上限，一口气写长文必然被截断。
- 产物是 Markdown 文稿，会落进「资产库」的**文档**分类，可以下载。
- **正文可以直接在画布上改**：节点浮框里点「编辑」打开大弹窗（约 1038×600，等宽字体），改完点「保存到节点」——**下游读的就是你改过的这份，不必重跑整条链**。节点上会挂一个「正文已手改」标记，弹窗里点「取消手改，用生成结果」即可还原。
  - 为什么要这样：一份 2400 字的分镜，可能只需要改一个角色名；为此让 LLM 重跑一遍既慢又费钱，还未必改对。
- 没有手改时，节点上与浮框里显示的仍是生成结果；**改过的正文不会因为重跑节点被悄悄丢掉**，要不要用它始终由你决定。

### 资产链：让角色在每一张图里长得一样

自动链铺到 L2，末尾会多两个节点：

1. **资产表**（文档节点）把剧本/分镜里出现过的角色、场景、道具整理成一张 Markdown 表格：

```
| 中文名 | 类型 | 英文视觉描述 | 出现场次 |
| --- | --- | --- | --- |
| 暮光闪闪 | 角色 | Twilight Sparkle, purple unicorn, blue mane with pink stripes | 全片 |
| 永恒花园 | 场景 | crystal castle garden, white marble, blooming flowers | S01,S02 |
```

表格是普通 Markdown，可以直接手改，改完重跑下一步即可（不用重新问模型）。

2. **资产设定图**（图片节点）读这张表，**一行资产生成一张设定图**：角色出三视图 + 面部特写，场景出广角空镜，道具出多角度产品图。浮框里的「生成范围」可以只出角色 / 只出场景 / 只出道具，先把最贵的部分挑出来跑。

3. 生成后的每张图都带着**资产名**进资产库。之后任何下游图片 / 视频节点，只要提示词里**提到这个名字**（例如"暮光闪闪 站在永恒花园的门口"），执行时会自动把这些资产的设定图挂成参考图——不用手动选图。上限 3 张，可在浮框里关掉这个开关。

> 资产表解析是宽容的：表头可有可无、3~4 列都收、坏行跳过；万一模型没写成表格，还会退一步认 `- 名称（类型）：描述` 这种列表写法。

### 风格库：让全片是同一个味道

在小说 / 剧本 / 分镜 / 分镜图 / 视频节点的浮框里选一个「风格」，它会自动注入三个地方：

| 注入点 | 内容 | 用哪份字段 |
| --- | --- | --- |
| 创作 Agent 的系统提示词 | 镜头语言、光影色调、节奏与剪辑、代表技法 | `agent_prompt`（中文，**可以出现导演名**——它的作用是帮 LLM 理解技法） |
| 生图提示词 | 英文技法词 + 约束词 | `image_prompt` / `negative_prompt`（**只写技法，不含导演名**） |
| 生视频提示词 | 英文运镜与节奏词 + 约束词 | `video_prompt` / `negative_prompt`（同上） |

内置 12 张：斯皮尔伯格·面孔、卡梅隆·奇观、诺兰·实感、王家卫·暧昧、韦斯·安德森·对称、宫崎骏·自然、昆汀·张力、维伦纽瓦·静默，以及国漫、赛博朋克、水墨、纪实手持。

> **为什么字段要拆开**：导演名甩给生图模型既有肖像与版权风险，也容易撞平台关键词审核。所以这条边界直接落在数据层——`image_prompt` / `video_prompt` 两个字段里出现导演名是「数据错误」，不是风格问题。风格卡全部可在「系统设置 → 导演风格」里改，改完立即生效。节点浮框里点「同步到全链」可以把当前风格一次性套到所有支持风格的节点上。

### 分镜图：一镜一张

**分镜图**节点读上游分镜表，**逐镜出图**：

- 每镜用它自己的「首帧提示词」（没有则退回「画面」描述）；
- 自动追加所选风格的技法词与约束词；
- **每一镜单独做一次角色提及注入**——分镜的「画面」行里通常写着角色中文名，于是镜 1 只会挂到暮光闪闪的设定图，镜 2 只会挂到云宝的，而不是把整批设定图全塞进去；
- 上游整批图片不会带进来（那样只会稀释主体），但节点上手选的参考图会应用到每一镜；
- 浮框里可以设「生成镜数」（0 = 全部，上限 24 镜），先用 2-3 镜试出味道再跑全片。

> 分镜表解析同样宽容：`### 镜头3 | 中景 | 缓慢推近 | 4s`、整行加粗的 `**镜头3 | ...**` 都认；`- 画面：`、`* **画面**：`、`画面:` 都认；「镜头清单 / 大纲」这类汇总标题不会被当成一个镜头。

### 接入本机 ComfyUI

1. 「模型服务」→「添加服务」，协议选 **ComfyUI**，Base URL 填 `http://127.0.0.1:8188`（API Key 留空），保存。
2. 在 ComfyUI 界面里把工作流调好 → 菜单「工作流 → 导出（API）」，得到 `workflow_api.json`。
3. 回到画布，添加「**ComfyUI 工作流**」节点，在浮框里点「上传」选择该 json。后端会自动扫描图里的节点，把可调项列成表单：模型、步数、CFG、采样器、宽高、帧数、提示词、种子、参考图槽位。
4. 想临时改分辨率、时长、步数，直接在浮框表单里改（不用回 ComfyUI 界面）；接上上游节点后，上游文本会覆盖工作流里的正向提示词，上游图片会填进参考图槽位。
5. 点「运行此节点」，产物（图片或视频，按工作流里的保存节点判定）自动落库并下传下游。ComfyUI 启动后点浮框里的刷新按钮可补全模型/采样器下拉项。

> 注意：`workflow_api.json`（API 格式）和 `workflow.json`（界面布局格式）是两种文件，程序对接用的是前者，必须从「导出（API）」菜单导出。

接入的实现细节、端点清单、产物定位与踩坑记录见 [docs/comfyui.md](./docs/comfyui.md)（对照 ComfyUI 官方 `server.py` / `execution.py` 源码逐条核实过）。

打开「**系统设置**」，你会看到这些可管理的内容（Tabs 由后端注册表自动生成）：

| 导演风格 | 12 张风格卡的镜头语言、光影色调、技法描述，以及三份注入片段（给 Agent / 给生图 / 给生视频）。新增一张风格卡 = 插一行，画布上的风格下拉自动出现 |

### 想让功能"活"起来，改哪里

| 想加的东西 | 怎么做 | 要动核心代码吗 |
| --- | --- | --- |
| 新增一个模型服务商 | 「模型服务」里填地址与 Key（或先加一条预设） | 不需要 |
| 新增一个参数档位（如视频 15 秒） | 「系统设置 → 参数选项」加一行 | 不需要 |
| 新增一种能力（如音频） | 「系统设置 → 能力类型」加一行 + 补一个适配器 | 不需要 |
| 新增一个可调配置 | 「系统设置 → 系统配置」加一行 | 不需要 |
| 新增/隐藏一个导航入口 | 「系统设置 → 导航菜单」改一行 | 不需要 |
| 新增一种模型协议（如 Gemini） | 在 `backend/app/providers/` 加一个适配器文件，然后在 `app/registry/adapters.py` 末尾 `register(...)` 一行 | 只加文件，不动框架 |
| 新增一个画布节点类型 | 在 `app/registry/canvas_nodes.py` 的 `NODE_SCHEMAS` 加一条声明式契约（`features` 决定属性面板控件，`handles` 决定端口与连线类型） | 只加注册，不动框架 |
| 新增一张配置表 | 建 ORM 模型 + 一条 Alembic 迁移 + 在 `app/registry/schema_registry.py` 注册一条 | 只加注册，不动框架 |

新注册的配置表会**自动获得**列表/新增/修改（乐观锁）/删除/审计/回滚/管理 API，前端「系统设置」也会**自动多出一个 Tab**——不需要改前端的任何一行代码。

## 更新与版本

打开「系统设置 → **关于与更新**」，可以看到当前版本、代码提交、安装方式与安装位置。

**配置更新源**（一次即可）：到「系统设置 → 系统配置」，把 `update.repo` 填成 `用户名/仓库名`。
`update.source` 选 `gitee` 或 `github`（默认 `gitee`，国内更快）；配置的源不通时会自动尝试另一个，
所以两个平台都发布的话不用来回改。启用了 `update.check_on_start` 时，打开界面会静默检查一次，
有新版本就在侧边栏「系统设置」上点一个小圆点，不打扰你。

**按安装方式的能力不同**（不做做不到的事）：

| 安装方式 | 一键更新 | 说明 |
| --- | --- | --- |
| `git clone` | ✅ 可用 | 工作区干净时执行 `git pull --ff-only`；`backend/requirements.txt` 变了才装依赖，`frontend/` 变了才重建界面。有未提交改动会**拒绝更新**，避免覆盖你的修改 |
| Docker | ➖ 只提示 | 容器内不自我更新，界面会给出 `docker compose pull && docker compose up -d` |
| 下载压缩包 | ➖ 只提示 | 引导去 Releases 下载新版覆盖；`data/` 目录（数据库、生成的图/视频）可以直接保留 |

更新完成后需要**手动重启服务**（关闭窗口后重新运行 `start.bat` / `start.sh`）——
不自动重启是有意为之：进程杀掉自己不可靠，宁可让你点一下。

## 安全说明

- API Key 使用 Fernet（AES）加密后存入本地 SQLite，密钥文件位于数据目录，请妥善保管、不要随数据目录一起分享。
- 默认只监听 `127.0.0.1`，外网无法直接访问。暴露到局域网或公网时，**务必设置 `APP_PASSWORD`**，并自行评估网络风险。
- 本项目不收集任何遥测数据，不内置任何统计或埋点。

## 常见问题

**Q：打开之后什么都用不了，顶部说「还没有接入任何模型」？**
A：这是预期的——所有创作功能都要先有一个模型服务。两条路都在那条横幅上：点「去接入模型」后**把一个 Key 粘进顶部的输入框**（会自动认出是哪家、测通了才保存），或者点「接入本机 Ollama」把本机已经装好的 Ollama 一键接进来（不需要任何账号）。只想先看看能做出什么，就在首页点「从示例开始」。

**Q：本机 Ollama 明明在跑，界面却说「没检测到」？**
A：点一次「重新检测」（检测结果有 60 秒缓存）。仍然不行时确认 Ollama 监听在 `127.0.0.1:11434`；Ollama 的模型清单接口偶尔要两三秒才回，应用已经把等待上限放宽到 4 秒，但如果它更慢，就会先按「没检测到」处理。

**Q：粘了一个 Key，它认成了别家的服务商？**
A：有些厂商的 Key 形状完全相同（DeepSeek 与通义千问都是 `sk-` + 32 位十六进制），机器分不开。应用会先按形状排好候选、逐个试一次真实请求；都试不通时会把候选列出来让你自己挑，也可以选「测不过也保存」。挑错的表现是连接测试报 401/404，换一个再试即可。

**Q：便携包解压后双击 `start.bat` 报错？**
A：多半是下错了包——要去 Releases 下载带 `portable` 的那个附件，而不是源码页自动生成的 `Source code (zip)`（那是源码，没有运行时）。若确认是 portable 包仍报错，看包内 `README-PORTABLE.txt`，里面写了端口占用与依赖自检的处理办法。

**Q：生成时报「连接失败 / All connection attempts failed」？**
A：先在「模型服务」里点「测试连接」。多数是 Base URL 错误（需包含 `/v1`）、Key 失效，或本机网络无法访问该服务商。现在这类错误会附带一句该往哪儿查的提示（是连不上、超时，还是代理问题）。

**Q：图片/视频参数（比例、时长等）不生效？**
A：不同模型支持的参数不同，不支持的参数会被自动忽略，请以模型官方文档为准。

**Q：视频生成要等多久？任务会丢吗？**
A：通常 1-5 分钟。任务在后台执行，关闭页面不影响；服务重启后未完成任务会被标记并给出明确状态，已完成产物不会丢失。

**Q：如何备份？**
A：备份数据目录（默认 `backend/data`，Docker 为根目录 `./data`）即可，里面包含数据库和全部媒体文件。

**Q：点了「一键更新」但按钮是灰的？**
A：三种情况：① 不是 `git clone` 安装（README 里的压缩包/Docker 方式），请按界面提示手动升级；② 本地有未提交改动，先 `git commit` 或 `git stash`；③ 还没配 `update.repo`，去「系统设置 → 系统配置」填上 `用户名/仓库名`。更新完成后记得重启服务。

**Q：出了错想反馈，需要提供什么？**
A：先自己看一眼，多数问题不用问别人：任务中心里每张任务卡片都有「日志」按钮，能看到这个任务执行期间发生了什么。如果还是看不懂，去「系统设置 → 关于与更新 → 日志与诊断」点「导出日志」，它会生成一份诊断报告（环境体检结论 + 最近 200 条错误与警告），可以先在界面上完整看一遍，再复制或下载成 `.txt` 发给作者。

报告里的接口密钥、URL 查询参数、系统用户名与家目录路径都已经替换成占位符，**不包含提示词、作品正文、图片或数据库内容**。完整日志在 `backend/data/logs/app.log`（单个文件上限 5 MB、保留 5 份），备份 `data/` 时一并带走即可。

**Q：start.bat / start.sh 某一步一直失败，怎么办？**
A：先跑一次环境体检，它会照着「哪一步不行、为什么不行、下一步做什么」给出结论：

```bash
python backend/tools/env_report.py
```

最常见的一类是**用错了 Python**：如果 `python` 指向的是精简版 / 嵌入式 Python（ComfyUI 整合包里自带的那种，没有 `venv` 模块），虚拟环境根本创建不出来，于是「安装后端依赖」这一步会反复失败。体检会把这种情况直接点出来（会打印「当前 Python 缺少标准库模块：venv、ensurepip」）。处理办法是从 python.org 装一个官方 Python 3.11 或 3.12，并确认 `where python` 的第一个是它。

如果看不懂体检结果，跑下面这条，把整段输出发给作者即可——**报告里只有环境信息，不含任何 API Key、密钥或数据库内容**：

```bash
python backend/tools/env_report.py --report
```

# 五类程序化视频同题对照

使用五份相同的合成简报。Codex 一侧直接编写经过校验的分幕配置，每题调用一次本地渲染。工坊 Agent 一侧用真实 DeepSeek V4.1 Flash，开启思考模式，让它自己读取技能、选择布局和组装参数。两边的 MP4 都由同一个本机 FFmpeg 渲染器生成。测试实例只启用了文本模型，媒体生成模型未参与。

| 场景 | Codex 的设计 | 旧版 Agent 的可观察策略 | 升级后 Agent 的执行 |
| --- | --- | --- | --- |
| 片头 · 横屏 4 秒 | 两幕分别承载标题和开场句。统一用上移淡入。 | 两幕都选择标题卡和淡入上移，主要差别在配色。2 次工具调用。 | 保留文本和两幕各 2 秒。2 次。 |
| 数据可视化 · 横屏 5 秒 | 一幕内放三根条形，长度和增长速度由原始数值 24、42、60 计算。 | 把三个数写成一行副标题，交付时说明缺少条形图。2 次。 | 选择 `bars`，传入三组原始数字，由渲染器计算比例和动效。2 次。 |
| 步骤教程 · 方形 6 秒 | 三幕各 2 秒，步骤编号独立排版。 | 把编号拼进标题，另加误差、水温等简报未提供的细节，渲染后回查资产。3 次。 | 使用独立步骤字段。保留 18g、270g 和原步骤顺序。2 次。 |
| 竖屏促销 · 5 秒 | 价格作为主视觉，行动文案放在色块按钮上。 | 标题放价格，其余文字拼成副标题，没有独立按钮。3 次。 | 使用价格和行动文案字段。中间轮曾擅自加「仅此一天」，最后一轮按用户给定文案成片。2 次。 |
| 倒计时 · 横屏 5 秒 | 同一幕持续显示标题，中间数字按秒从 5 变到 1。 | 额外查本机引擎，拆成 5 张每张 1 秒的卡片，渲染后再查资产。4 次。 | 选择单幕 `countdown`，由渲染器计时并绘制居中数字。2 次。 |

这五组里，直接执行从输出规格逆推布局，模型旧版则在遇到缺失能力时用标题卡拼近似效果。升级提供了明确的结构化布局和交付证据。五组 Agent 工具调用由 14 次降到 10 次，最终每组都是 `load_skill → render_motion_video`。这个数字只代表本次样本。

## 改动与验收

- 扩展本地渲染器，支持比例条形图、编号步骤、价格与按钮、逐秒倒计时，与原标题卡兼容。
- 用布局相关的字段校验拦截缺失参数。技能要求保留给定的数值和文案，避免新增促销期限、库存或其它未经提供的承诺。
- 返回 FFprobe 验证过的时长、尺寸、帧率和编码，并附分幕结构、原始图表数据或计时区间，供 Agent 直接交付。
- 两组各五条视频均用 FFprobe 检查。逐帧抽样检查了条长、开场增长和居中数字的变化。

## 复现

测试解释器需具备仓库后端依赖与 Pillow，本机需具备 FFmpeg 和 FFprobe。Agent 实测使用已配置的 DeepSeek 文本服务，可能产生文本费用。当前样片存于 `dist/motion-comparison`。

```powershell
python backend/tools/agent_motion_comparison.py direct dist/motion-comparison/codex
python backend/tools/agent_motion_comparison.py agent dist/motion-comparison/agent-final
```

可传 `--case 02-data` 只复跑数据可视化。每轮会保存各题的参数和调用记录。

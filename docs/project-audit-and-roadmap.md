# 小马 AI 工坊项目审查与产品路线（修订版）

审查基线为 v2.2.3，提交 `78de46a`，修订日期为 2026 年 11 月 23 日。本文在初版审查稿的基础上，按代码复核与评审意见修订；初版保留在原始附件中，未改动。产品定位仍按「本地单机、用户自带模型密钥」为前提。

## 结论

优先让整张画布可恢复、让单镜头可补跑，再把成熟工作流做成可复用表单。这样可以减少中断后的进度损失、重复付费和成片返工。

项目已经具备多模型适配、Agent 搭画布、调用量预估、产物版本与候选选片、角色参考图、逐镜视频和本机后期。建议围绕「从分镜到成片」完善这些能力，继续使用 FastAPI、SQLite WAL 和本地文件。等多人并发或多进程调度成为明确需求，再评估 PostgreSQL、独立任务进程和对象存储。

**采纳初版的三条主线，但实施顺序做一处调整**：先补齐「测试隔离 + 媒体授权设计」，再做运行恢复与备份。前两件便宜、可立刻验收，而且媒体授权如果先按 Bearer 做，后面会因为 `<img>` / `<video>` 发不了请求头而返工。

## 〇、本次修订要点

1. **媒体授权不能只加 Bearer**：原片、缩略图、下载由浏览器标签直接发起，必须用 HttpOnly Cookie 会话或登录后签发的短期媒体 token，并保留 Range。
2. **测试隔离升为 P0**：初版记录的两项失败不是「临时库没迁移」，而是有测试修改全局 `settings.DATA_DIR` 后不复原。需要 `conftest.py` 自动保存/恢复，并让 CI 在全新库上跑迁移与全量测试。
3. **运行恢复增加「不确定态」**：供应商未必支持客户端幂等键，提交前落库、重启后可查则续挂、查不到标 `unknown` 让人确认，不能盲目重发付费请求。
4. **备份分两档**：配置 + 数据库 + 素材清单是小备份，升级前自动做；含全部生成产物的全量备份手动触发，并检查磁盘空间。
5. **镜头工作台是现有数据的视图**：复用已有的分镜图、候选与版本，先把稳定 `shot_id` 落进 schema，再做增量执行；不另起一套候选概念。
6. **前端体积按 gzip 后计**：画布约 89 kB、3D 模块约 144 kB（压缩前 275 / 558 kB），性能预算应以线上传输体积和节点数实测为准。

## 二、同类产品调研

本节依据各产品公开资料，建议项结合现有仓库能力提出。

**首选新功能是镜头工作台。** 但它应该是现有数据的视图，不是又一条流水线：分镜图、候选、版本已经能表达「同一镜多版本」，首版只补三件事——稳定镜头 ID、审核状态、按镜补跑。用 12 镜样例验收：修改第 7 镜并生成新候选，其余 11 镜的已选结果保持有效，最终可以导出新版粗剪。

**现在不建议做**：PostgreSQL、独立任务进程、对象存储、多人权限体系、3D 编排与实时渲染优化。这些都要等「本机单人从分镜到成片」这条主链路稳定后再评估。

## 三、镜头工作台首版定义

| 能力 | 首版范围 | 明确不做 |
| --- | --- | --- |
| 镜头身份 | 新增稳定 `shot_id`（分镜表逐镜生成时落库），现有项目迁移时按顺序补号 | 不改写已有分镜内容 |
| 候选与定稿 | 每镜一行展示已有候选图 / 视频，标记「已选」与「待审」 | 不做跨项目的候选池 |
| 按镜补跑 | 只重跑选中镜头，复用其余镜头的已选结果 | 不做整链自动重排 |
| 送导演台 | 选中的镜头按顺序送入导演台，生成新版粗剪 | 不在本轮做成片模板 |

验收用 12 镜样例：改第 7 镜后只新增第 7 镜候选，其余 11 镜的版本与选择不变；导出粗剪的镜头顺序与选择一致。

## 五、实施顺序

0. **补齐保命项（先做）**：测试隔离与 CI 基线、媒体授权设计（Cookie / 签名 token + Range）。过线条件：全新空库全绿；开启口令后未授权媒体被拒、授权播放与拖动正常。
1. **让运行与升级可恢复**：`run_steps` 检查点、付费请求去重、轻备份与升级前自动快照、全量备份手动入口。过线条件：中断续跑不重复付费；旧版本项目可恢复；密钥不随备份带走。
2. **让改稿与补跑更省**：稳定 `shot_id`、画布修订号、`input_hash` 增量执行、镜头工作台。以「只重做指定镜头并导出粗剪」为阶段验收。
3. **让工作流能复用**：版本化节点组与本地工作流表单，发布首批模板并提供模型依赖预检。将运行阶段采集的请求记录用于费用估算与实际用量展示。

## 六、本次验证记录

- 前端 TypeScript 检查与生产构建通过。Vite 报告一个超过 500 kB 的 3D 模块（压缩前 558 kB，gzip 后约 144 kB，已懒加载）。
- 后端全量测试 **1,253 项通过**（2026-11-23，提交 `78de46a`）。初版在未迁移临时库上出现的 2 项失败，复核为测试修改全局 `settings.DATA_DIR` 未复原导致的隔离问题，已列入 P0 修复项；与迁移无关。
- 本轮优化后实测：`/api/meta/setup-status` 冷请求 12–24 ms；`/assets/*` 主包 gzip 后 72.5 kB；缩略图首次生成后缓存命中 5–6 ms。
- 未验证：真实付费模型、浏览器主链路的完整回归、100 节点以上画布的拖动与保存压测。本轮审查与修订未修改业务源码。

### 第 0 步落地记录（2026-11-23）

- **测试隔离**：新增 `backend/tests/conftest.py`，每个用例独立空数据目录、收工后逐个复原 `settings` 字段；会话开始时对全局库跑一次幂等迁移。在**全新空目录**（`DATA_DIR` 指向刚建的临时目录）跑全量测试：**1,272 项通过**（2:47），不再需要先手工启动一次应用。
- **媒体授权**：登录接口额外下发 HttpOnly Cookie（SameSite=Lax，30 天），`require_auth` 同时接受 Bearer / `?access_token=` / Cookie；`/media` 换成带校验的 `AuthStaticFiles`，`/media-thumb` 挂同一道鉴权，Range 仍由 Starlette 处理。真实服务实测：未登录 `/media` 与 `/media-thumb` 均 401，登录后 200，`Range: bytes=0-3` 返回 206；口令未设置时一律放行。
- **CI 基线**：新增 `.github/workflows/ci.yml`，在全新空库执行迁移（并打印建出的表）、跑后端全量测试、前端 `npm ci` + 构建。
- 附带修复：伪造令牌的 base64 非法时 `verify_auth_token` 会抛异常（500），改为返回 False；`.js` 的 MIME 断言兼容 `text/javascript` 与 `application/javascript`（Windows / Linux 取值不同）。
